# Nailbot — Redis → SQLite Migration Guide

**Цель:** Безопасно перенести исторические данные из Redis в SQLite с максимальной наблюдаемостью и возможностью отката.

**Текущий статус:** Инструмент (`migrate_legacy_data.py`) готов к использованию на реальных данных. Все критические механизмы безопасности реализованы.

## Текущее состояние инструмента

`migrate_legacy_data.py` — мощный, безопасный и наблюдаемый инструмент миграции.

### Основные возможности

| Режим                    | Что делает                                      | Когда использовать                     | Безопасность |
|--------------------------|--------------------------------------------------|----------------------------------------|--------------|
| `--readiness-report`     | Глубокий анализ данных + оценка рисков           | **Обязательно** перед любой большой миграцией | 100% безопасно |
| `--simulate`             | Детальные планы изменений по каждому клиенту     | Понимание, что будет сделано           | 100% безопасно |
| `--dry-run`              | Симуляция с реальной БД + проверка конфликтов    | Финальная проверка перед `--full`      | 100% безопасно |
| `--full`                 | Реальная миграция (запись в БД)                  | Только после всех проверок             | **Высокий риск** — используй с умом |
| `--verify`               | Пост-миграционная проверка состояния БД          | После `--full`                         | 100% безопасно |
| `--checkpoint` + `--resume` | Сохранение прогресса и возможность продолжить   | Любые длинные миграции                 | Критично важно |

### Автоматическая защита при `--full`

- Автоматический бэкап БД перед записью (`backups/`)
- Подробный `migration_execution_log_*.json` (до/после по каждому клиенту)
- Автоматически генерируемый `migration_summary_*.md` (человекочитаемый отчёт)
- Поддержка `--checkpoint` + `--resume`

## Рекомендуемый workflow (НЕ НАРУШАЙ ПОРЯДОК)

### 1. Подготовка данных
```bash
# Получи свежий экспорт с сервера (json.gz)
```

### 2. Readiness Report (обязательно!)
```powershell
python migrate_legacy_data.py --readiness-report --data-file "твой_экспорт.json.gz"
```
- Смотри Risk Level
- Читай риски и рекомендации
- Если риск высокий — разбирайся перед продолжением

### 3. Симуляция с планами
```powershell
python migrate_legacy_data.py --simulate --data-file "твой_экспорт.json.gz" --limit 200
```

### 4. Dry-run на реальной БД (с чекпоинтом!)
```powershell
python migrate_legacy_data.py `
  --dry-run `
  --data-file "твой_экспорт.json.gz" `
  --db "путь/к/твоей/базе.db" `
  --checkpoint "progress.json" `
  --limit 500
```

### 5. Реальная миграция (только когда уверен)
```powershell
python migrate_legacy_data.py `
  --full `
  --data-file "твой_экспорт.json.gz" `
  --db "путь/к/твоей/базе.db" `
  --checkpoint "progress.json" `
  --resume `
  --yes `
  --limit 500
```

### 6. Пост-миграционная проверка
```powershell
python migrate_legacy_data.py `
  --verify `
  --db "путь/к/твоей/базе.db" `
  --execution-log "migration_execution_log_....json"
```

---

## Полезные флаги

- `--limit N` — обрабатывать только первые N клиентов (всегда используй на первых прогонах)
- `--offset N` — пропустить первые N клиентов
- `--checkpoint file.json` + `--resume` — спасение при обрывах
- `--no-backup` — отключить автоматический бэкап (не рекомендуется)
- `--execution-log file.json` — использовать при `--verify` для сравнения

---

## Что генерируется после `--full`

После успешной реальной миграции ты получаешь:

1. `migration_execution_log_YYYYMMDD_HHMMSS.json` — самый важный файл
   - По каждому клиенту: до/после счётчиков + все действия по букингам с причинами

2. `migration_summary_YYYYMMDD_HHMMSS.md` — красивый отчёт для тебя/команды

3. `migration_report_full_....json` — технический JSON-отчёт

4. Бэкап БД в папке `backups/`

## Следующие этапы (Фаза 2+)

- Фаза 2: Тестирование на реальном прод-дампе (dry-run + верификация)
- Фаза 3: Проведение миграции батчами на проде
- Фаза 4: Архитектурный переход (SQLite как источник правды)

---

**Главное правило (обязательно к соблюдению):**

> Никогда не запускай `--full` на копии прод-БД без выполнения по порядку:
> 1. `--readiness-report`
> 2. Несколько итераций `--dry-run` с `--checkpoint`
> 3. `--verify` после тестовых прогонов

## Откат и безопасность

- Перед каждым `--full` автоматически создаётся бэкап БД в папке `backups/`.
- Все изменения логируются в `migration_execution_log_*.json` с before/after.
- При обрыве используй `--checkpoint progress.json --resume`.
